# v0.8.4 仮説検証：位置付き管理行と後続欠落の小計

## 本人端末から得た匿名情報（2026-10-28）
v0.8.3 / PaddleOCR / POSITIONED。候補は8件。管理情報由来の誤候補[1]は row=7、adminSignals=1、identifierShape=true、aboveDate=false、itemsBefore=0、ITEM_POSITIONED_AMOUNT。小計由来の誤候補[8]は row=17、smallHeading=true、countHint=true、amountColumn=true、sumMatches=false、futureSummary=false、itemsBefore=7、ITEM_POSITIONED_AMOUNT。個別の原文・実番号・画像は収集していない。

## コード上の切り分け
- [1] は日付より下なので従来の「日付より上の管理領域保留」が適用されない。管理信号が1つしか認識されず、2信号以上の別ゲートも通らない。
- [8] は後続の税・合計を認識できていない（futureSummary=false）。従来の structuralSubtotal はこの条件で**直ちに処理を終了**する。従って金額一致/不一致以前に小計判定が外れていた。
- さらに先頭の誤候補によって itemSum の整合判定が汚染され得るが、これは独立の追加要因であり、実機での値の直接検証ではない。

## 限定修正
- `店:012` 等の先頭にある独立した管理番号ラベルを2番目の管理信号として認識する。単独の`レジ袋`や`取引No.1ガイド`などは除外しない。
- 後続集計が見つからない場合、商品が既に2行以上あり、非常に短い小計風見出し（認識文字揺れを許容）、点数、整列した金額列が揃う場合だけ**集計らしい行を保留**する。小計金額を推測/登録しない。真正の商品名 `小豆8点`、`小計8点セット` を保護する。
- OCRの原文・番号は増やさず、位置と商品判定の合成試験を追加。79円×2点と245円×2点を保持。
- 初期費用・権限・モデル・DB/JSON・通信・診断情報の共有方法は変更しない。

## 重要な限界
この変更で現物が6件になる保証はなく、提示された匿名信号だけではOCRが本当にどの文字を解釈したか分からない。失敗時は「さらにルールを緩める」より、未知のOCRの崩れに対する汎用的な保留規則と逆方向テストを優先する。mainへマージせず、CIと実機の合格までは試作品とする。
