# v0.4 OCR改善と検証記録

v0.3で実機から報告された誤候補を受け、商品以外の除外と確認前の保存防止を優先した開発版です。実レシートの合格判定は未完了です。

## 変更

- Tesseract4Android 4.9.0（既存エンジン）を継続。外部OCR・SDK・依存ライブラリは追加していません。
- EXIF回転・反転、局所背景補正、文字範囲の切り出し、±5度の投影による傾き補正。元画像AUTO、補正画像AUTO、補正画像SINGLE_BLOCKを比較し、一つの全文だけを採用します。認識結果を混ぜないため、同じ明細を複数回追加しません。
- 商品・店名・日付・数量・小計・税・総額・割引・支払を分離。合計後の不明行は商品にしません。集計・支払の見出しの一文字OCR誤りも保守的に除外します。
- 次行の数量・金額、単価×数量、行末8%/10%・※/軽などを扱います。「卵10個」は商品規格として保持し、購入数量10にはしません。印の意味、単価、数量、税込区分を推測で確定しません。
- 店名・日付は今回の認識値のみ入力。未認識・競合は空欄。前回店名や今日の日付で埋めません。
- 候補はすべて未選択、税込単価は空欄。利用者が数量と「行金額が値引後税込合計」と確認した場合のみ、整数で割り切れる単価を計算できます。
- 原文・行金額・印字単価を表示し、数量・税込単価・税率は縦並びのラベル付き入力。選択合計とレシート総額、入力単価×数量と各行金額の相違を保存前に警告。割引は商品へ自動配分しません。一括保存は既存のSQLiteトランザクションを使用します。

## 再現手順

JDK 17、Gradle 8.11.1、SDK 35、Build Tools 35.0.0。

```sh
sh tests/test-price-math.sh
sh tests/test-parser.sh
sh tests/test-ocr-image.sh
sh tests/privacy-sanity.sh
sh scripts/fetch-ocr-models.sh
gradle :app:assembleDebug :app:lintDebug --no-daemon --max-workers=2
```

価格計算7件、解析32件、画像補正5件。解析試験は架空データだけを使い、非商品除外、複数行、印字数量・単価、規格の保持、未知値、税区分記号、総額矛盾・割引、日付・店名競合、負金額、数値・全文・行数・行長の上限を確認しています。

画像OCRの比較は任意の開発用検証です。Pillow・numpy・JDK・Tesseract CLIとNoto Sans CJKフォントがあるLinux上で実行します。

```sh
python3 tests/ocr-benchmark.py
```

生成・認識する画像はスクリプト内の架空レシートだけです。一時ディレクトリを削除し、結果は件数等の集計だけを出力します。アプリと共通のReceiptImageをJavaデスクトップ用ハーネスで実行しています。CanvasとJava2Dの補間やAndroidネイティブ版との差は実機確認が必要です。

## プライバシー・セキュリティ

アプリのINTERNET・位置・カメラ権限、広告・診断送信、バックアップ設定、外部Intentの宛先は追加・変更していません。OCR全文・画像をログへ出しません。画像は縮小後400万画素まで、OCR全文32,000文字、500行、1行240文字、候補80件、行金額100万円以下。並行OCRを抑止し、Javaメモリ不足時には縮小・再撮影を案内します。撮影キャッシュはOCR成功・失敗とも削除します。

OCRモデルはコミット87416418657359cb625c412a48b6e1d6d41c29bdとSHA-256で固定。既存キャッシュも検証し、不一致の取得物は使用しません。実画像・購入データ・署名鍵を追加していません。これらの確認は画像デコーダーやTesseract全体の脆弱性監査を代替しません。

## 残る制限と実機での合否確認

- 多数の店舗書式、かすれ・丸まり・透視変形・5度を超える傾き、小さい文字、手ぶれは未検証です。未知の見出し・複数列・商品名を厳しく除外することによる認識漏れも残り得ます。「非商品の誤候補が絶対にない」とは保証しません。
- 数量や税率がない場合は手確認が必要です。行金額を税込とみなす推定、割引自動配分、記号から8%への自動変換は行いません。総額が一致しても各明細の正しさは保証されません。
- 現行履歴は整数円単価です。1円未満となる割り算を自動で丸めません。現在の形式で正確に保存できない単価があります。
- 3回のOCRによる処理時間・ピークメモリと低メモリ端末、EXIF反転、画面操作・入力・SQLite保存の端から端までの確認はAndroid実機で行ってください。画面切替・回転・再解析では編集中の明細が保持されないため、画面内で警告しています。
- 日本語西暦日付を対象にしています。和暦・年省略・複数店舗名などは未確定になることがあります。
- インストール後はまず架空レシートで、税額・点数・支払が候補に入らないこと、初期チェックが0件、店名・日付未認識時が空欄であること、数量・単価・割引と総額警告を確認してください。その後、本人の端末内だけで実レシートを試します。個人情報を含む画像・認識文をGitHubやログへ送らないでください。

実機合格が出るまで「実用精度を達成」「安全に利用できる完成版」とは扱いません。
