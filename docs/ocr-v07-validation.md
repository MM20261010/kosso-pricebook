# v0.7 品目単価中心の明細確認

対象ブランチ `feat/unit-review-v07`、基盤 `feat/receipt-layout-v06` / `8de65fa`。PR #1→#2→#3 は未マージのまま、v0.7は #3 の上に積む。mainは変更しない。

## 変更と利用方法

- 通常の確認カードは商品名、`印字単価 × 購入数量 ＝ 行金額`、確認済み税込単価、短い要確認ボタン。名前をタップして修正できる。原文・管理記号・座標・分類・照合は閉じた詳細へ集約。比較・手入力も展開式。
- 「全商品を選択」は対象選択だけで、価格確認・保存はしない。初期状態は全件未選択、税込単価・確認税率も未確定。
- 選択商品の単価を一括確認できる。本人が価格区分・名称・数量・値引を確認した場合にのみ反映。数量不明を1点にする場合も専用の明示確認を必要とする。
- 税抜表示を税込と指定する操作、税込に税を重ねる操作は拒否。税抜は本人が税率と「1点単位の端数処理」を確認した場合のみ換算できる。税率混在は商品を分けて選ぶ。合計単位の端数処理・割引・分数単価は手入力。C/Vから税率を推測しない。
- 印字単価がない場合は、確認数量で行金額を整数除算できる場合だけ税込確認に利用できる。「印字単価」という証拠欄には逆算値を保存しない。
- 確認済み税込単価は税率不明でも保存できる。税率不明の履歴は税抜換算比較から除外。買い物メモは確認した税込単価を店舗別に表示する。
- 「商品コード/JAN/SKU」の列見出しがあり、別領域の長い数字がその列に揃い、商品名より左、別の金額が右にある場合に限って管理コードを分離。元のコードはメモリ内の詳細に保持する。文字列に埋まった型番・容量・不確実な数字は削除しない。C/Vが商品名に密着して区別できなければ残して要確認。
- 管理ラベル・支払・集計を商品と分離し、小計の後の未知の行を新商品にしない。`稅`などの税見出し表記揺れにも対応。店舗名は候補だけを通常表示し、番号を店舗名へ補完しない。番号が店舗区別に必要なら店舗名欄を本人が編集できる。
- 確認画面の編集はタブ切替と画面回転を通じてメモリ内で維持する。プロセス終了後の編集・検出座標復元は未対応。画像を選び直す必要がある。

## 保存と互換性

SQLite v1→v2はALTER TABLEによる追加で、既存購入履歴・メモを削除しない。確認済み税込単価・数量の旧列はそのまま利用。新列は印字単価、行金額、印字価格区分、容量・規格、税率確定の有無、原票集計参照。集計テーブルには小計・税額・合計とOCR候補であることを保存する。商品単価への税額自動配賦は行わない。購入明細と集計は同一トランザクションで保存する。

旧v1 JSONの復元を維持する。書き出しは `kosso-pricebook-v2`。v2を旧版へ渡して税率未確定を税率0%と誤解釈されないよう、形式名を分け、旧版は非対応として拒否する。v2はv0.7以降で復元する。旧版に戻す場合に備え、移行前のv1 JSONも保管する。復元は全検証後にトランザクションで置換する。

レシート画像の任意長期保管は今回見送った。既定で保存せず、比較中だけメモリに保持、撮影一時ファイルはOCR終了時に削除。画像・OCR全文・管理番号・座標はDB/JSONに保存しない。JSONには本人が保存した商品名・店舗名・日付・価格・集計が含まれる。外部カメラの写真保存やJSON保存先のクラウド選択は、相手アプリ側へデータが渡るため既存の注意を維持。
