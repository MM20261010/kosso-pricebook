# v0.8 明細抽出の不具合修正

基盤 `feat/unit-review-v07` / `c361252`。新ブランチ `fix/receipt-extraction-v08`。既存PR #1〜#4は未マージでmainを変更しない。新機能・OCRエンジン変更・依存追加・DB/JSON形式変更は行わない。

## 再現した原因と修正

1. **管理行**：v0.7は行頭の管理ラベルには対応していたが、店舗名にレジNo/担当者No/取引Noが連結すると抜けた。ラベルと数字の繰り返しを行中でも調べ、商品名を結合する前に管理行へ分類する。単独の商品名「レジ袋」「No.1珈琲」「取引ノート」まで除外しないよう逆方向試験を追加。
2. **小計**：誤字見出し `小汁8点` の点数が文字列へ混ざり、既知の `小汁` と一致せず商品になった。見出し・購入点数・金額を分離。表記揺れは明細計との一致、点数の併記、近傍の税/合計/支払行によって裏付ける。小計の後は未知の行も商品にしない。重なった領域は数値を確定せず、集計境界だけを維持する。
3. **数量**：v0.7は隣接行を結合した後、単価×数量の不一致を警告するだけで誤った数量を残していた。明示単価×数量が行金額と不一致ならその数量を流用しない。結合済みの不一致も数量/単価を未確定へ戻す。別行の裸の点数だけでは、対応する印字単価との一致がない商品へ付与しない。
4. **短いコード**：v0.7のコード分離は列見出しのある長い数字に限定されていた。v0.8は商品名/金額が別領域である複数行を基準に、左の数値列、右の金額列、既出のコード値を照合。2桁程度の独立領域、空白区切り、密着、独立したコード行に対応する。先頭2桁の一律削除はしない。

列見出しのないコード分離、とくに文字に密着した数字は**名称の提案**である。元の文字列・管理コードをメモリ内の詳細に残し、コード分離後の名称を本人が明示確認するまで保存できない。名称を戻して型番/ブランドを残す選択もできる。反復列の裏付けがない数字、既出コードに一致しない数字、容量・型番・ブランドを示す数字はそのまま保持する。数字と文字が完全に融合して区別できないケースは自動解決しない。

通常画面はv0.7の要約カードを維持。未確定のコード/数量だけを短く案内し、詳細・一括確認で修正する。候補は未選択で、価格区分・税率・端数・単価を自動確定/保存しない。数量1点は既存の「原票で1点と確認」操作で一括入力できるが、全体8点から個別に割り当てない。

## 架空の失敗構造による比較

`tests/shared/ReceiptExtractionTest.java` をJVMとAndroidで共用する。実画像や実管理番号の転記ではなく、固定の架空名称・架空座標・連番の架空識別子を生成。報告された取引番号の値は使わず、架空の `12,345` へ置き換えた。画像OCRのきれいな出力だけではなく、管理ラベルの連結、空白消失、小汁/小訐/小言十、密着コード、重複した数量行を含めた。

| 同一の破損OCR/座標データ | v0.7 | v0.8 |
|---|---:|---:|
| 商品候補 | 8 | 6 |
| 管理行/小計の誤候補 | 2 | 0 |
| 期待するコードなし名称 | 0/6 | 6/6（名称提案） |
| 79円×2＝158円 | 正しく対応 | 正しく対応 |
| 245円×2＝490円 | 正しく対応 | 正しく対応 |
| 359円の商品の数量 | 2（誤り） | 未確定（2を流用しない） |
| 小計 | 未認識 | 2,872円 |
| 税額 / 総額 | 268 / 3,140円 | 268 / 3,140円 |

行金額は6 / 158 / 1,460 / 490 / 399 / 359円、合算2,872円。2点を明記した商品は2種類・計4点。他4商品の数量は不明のまま、購入8点は照合用に分離する。商品の個別税率・端数は未指定なので税込単価へ逆算しない。

4形式の再現データに加え、見出しに似た正常名（小計ノート、小計8点セット、商品計量スプーン、合計ノート、小汁うどん）、レジ袋/No.1珈琲、16茶/21世紀ブレンド/3M/2in1、容量/規格/CV-20、独立した数字の型番、根拠のない密着数字、税率・数量・金額の境界を試験する。

これは制御した合成入力の比較で、本人の実レシートの再認識ではない。不要候補の除外操作2件と名称の個別修正6欄を、再現データ上で減らした。名称の確認操作と数量不明の確認は必要。実端末での手動修正回数や日常使用精度の改善は未検証であり、実用合格としない。
