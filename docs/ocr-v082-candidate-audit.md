# v0.8.2 候補別分類診断（開発・検証用）

## 根拠（2026-10-28 Android本人実機）
- v0.8.1（versionCode 9 / ソース 066a470）、同じレシート画像・PaddleOCR、解析経路 POSITIONED。
- 商品候補は8件のまま。商品と扱われた先頭の管理情報由来[1]と末尾の小計由来[8]の採用理由は、どちらも ITEM_POSITIONED_AMOUNT。
- STORE_HEADER と ADMIN_LABEL_STRUCTURE は別の行で見られた非商品判定。混同しない。
- 実写真、取引番号、OCR原文、履歴は収集もGitHub登録もしていない。
- 原因（OCR文字の崩れ・分割・位置・金額列・小計判定のどれか）は未特定。v0.8.1の実機改善は不合格。

## この変更の目的
実機で手入力や領域ログの探索を増やさない。候補番号1〜Nを最初に表示し、該当候補へ実際に紐付いた採用行（ITEM_POSITIONED_AMOUNT 等）と数量・商品名の補助行の理由、匿名化判定信号だけを開く。全領域の診断は折りたたんで残す。

- 対応は決定時に記録された `Decision.candidates` のみを使用。原文の類似度から候補を推定しない。
- 対応できない候補は明示的に「対応行なし」と表示し、推測しない。
- 各候補の詳細は折りたたみ、原文・正規化はさらに明示展開。スクショ禁止 FLAG_SECURE、保存・ログ・Intent送信は追加しない。
- 実データとOCRエンジン、DB/JSON、数量単価判定ロジック、Manifest、依存、権限は不変更。

4. 修正ロジックは、匿名信号・合成データの原因分析で根拠ができてから別途行う。6件への修正を保証しない。
