| 架空の条件 | v0.8.7候補数 | 旧信号 | 新診断の区別 |
|---|---:|---|---|
| 既知の厳密見出し・後続集計なし | 6 | smallHeading/countHint/amountColumn/sumMatches=true、futureSummary=false、itemsBefore=6、labelKind=OTHER | STRONG_HEADING=PASS / NO_FOOTER_HELD |

これは**実機にも句読点があるという証拠ではない**。旧コピーだけではこの差を知れず、きれいな見出しを固定した合成試験の成功が実機を保証しないことの制御実験である。
句読点を含む未知の実商品も勝手に除外せず、実機の新しい固定コードを得てから除外条件の変更を判断する。

## 修正した範囲

- 明示ラベル付きの単価だけ・数量だけを独立して保持する。数量または単価を割り算・総点数から補完しない。
- 別領域の明示ラベルを独立した商品と数えない。同じ行のラベル付き単価欄・数量欄は自分の行金額と照合する。
- 別行の情報は隣接・既存明細・不一致・競合を検査する。数量2が359円の商品へ流用されない従来回帰を維持。
- 小計の許可文字・見出し書式・除外条件は拡張しない。既存条件を、実判定と診断で共通の処理へ整理する。
  原本が不明な `小豆8点`・`小辻8点セット`・未知の小計らしい文字列を合算一致だけで除外しない。
- OCRモデル、画像処理、ncnn、商品名の字の置換、DB/JSON、保存方式は変更しない。
  商品名の実機文字精度は改善未確認。名称編集は引き続き任意。

## 端末内の診断とコピー

既存の「レシート詳細・集計・認識テキスト」→「ビルド・領域別の分類理由（端末内だけ）」へ集約する。

1. **REGION_TOKEN**: Javaへ渡った個々のOCR領域に数量表記が観察できるか。`PAIR` / `COMPLEMENTARY_FIELDS` / `PARTIAL_MARKER` / `NONE_OBSERVED` 等。
2. **LAYOUT / ROW_TOKEN**: 領域が単独か結合済みか曖昧か、組み立てた行に表記があるか。
3. **EXTRACTION**: 実際の抽出結果 `NONE` / `UNIT_ONLY` / `COUNT_ONLY` / `PAIR`。
4. **ASSOCIATION**: 実際に結び付いたか。`BOUND` / `INLINE_BOUND`、不一致 `AMOUNT_MISMATCH`、位置 `GEOMETRY_REJECTED`、競合 `FIELD_CONFLICT`、対象なし `NO_TARGET` 等。
5. **SUMMARY_STOP**: 実際に通った小計判定の停止条件。既知語幹 `KNOWN_STEM`、厳密見出し `STRONG_HEADING`、句読点込み `PLAUSIBLE_HEADING`、点数 `COUNT_CHECK`、金額列・明細計一致・フッターを固定結果として併記。

`NONE_OBSERVED` は「原本に印字なし」「OCR失敗」のどちらも断定しない。
例えばOCR領域に `PAIR` があるのに `EXTRACTION=NONE` なら行構築・書式対応側、抽出 `PAIR` で `GEOMETRY_REJECTED` なら関連付け側へ絞れる。
小計は `HEADING_NOT_ALLOWED`＋既知語幹/見出しの可否で未知の別字と既知ラベルの書式崩れを分け、`COUNT_CONTRADICTION` と `SUM_CONTRADICTION` も区別する。
印字あり/なしの判定には、端末内で原本とOCR領域を見比べる人の確認が必要。

**「全候補と未関連行の匿名診断をまとめてコピー」** で全体を1回で取得できる。順序は候補表示順。
従来漏れていた未結合行や、結合を試みて失敗した行も対象とし、「成功した結合」と区別する。

コピーは閉じたenum語彙の固定フィールド・結果・理由コードだけ。店名・商品名・金額・数量値・日付・番号・OCR原文・座標・行番号・候補番号・任意の自由文を含めない。
従来の「大文字なら理由コードとして通す」処理も廃止し、未登録の理由は `UNAVAILABLE` にする。文字列のevidenceはコピーしない。
コピー文字数/行レコードに上限を設ける。明示操作のみで、クリップボードの機密フラグを維持する。
原文・座標・実データとの対応はFLAG_SECURE付きの端末内詳細にのみ表示し、診断をファイル・DB・ログへ保存しない。
自動送信、共有Intent、新規権限、診断SDKは追加しない。
