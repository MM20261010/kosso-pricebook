# v0.8.6: 「小辻8点」のOCR崩れを保留扱いにする限定修正

## 前回の実機根拠
v0.8.5では先頭の管理番号を除いた商品6行＋末尾の小計誤候補1行＝7候補。スクリーンショットを拡大すると、誤候補の見出しは「小辻8点」と読める。匿名診断は `smallHeading=true, countHint=true, amountColumn=true, sumMatches=true, futureSummary=false, itemsBefore=6, labelKind=OTHER`。
「計→辻」のOCR誤読は画像の視認に基づく推定であり、アプリ内部のコードポイント一致は新実機試験まで未確認。

## 限定修正
- `strongSubtotalHeading` と `plausibleSubtotalHeading` に「小辻」を追加。**商品名全体を曖昧一致させない**。
- 税/合計フッターが無い「小辻」では、先行商品行金額合計との一致、既知数量＋各数量不明商品最低1点と印字点数の整合性を満たす場合だけ保留にする。
- 保留した候補は商品に追加しないが、小計金額と購入点数を確定せず、ローカルの分類診断に残す。誤除外を起こす余地はあるため元レシートの保存前確認は継続。
- 検証用に架空の6商品＋「小辻8点」＋後続フッター無しを追加。79円×2と245円×2保持、金額/点数が不一致の「小辻8点」「小辻2点」および「小辻8点セット」が商品として残ることを逆方向テストする。
- その他のOCRモデル・通信権限・DB/JSON・価格保存方式は不変更。

## 状態
コード＋テストを登録。GitHub ActionsのJVM/Android実行前、実機再検証前。6件になる保証はまだない。
次の大きな課題：商品名の忠実性と単価・数量の紐付け、続いて架空の20/50行の長いレシート回帰。
