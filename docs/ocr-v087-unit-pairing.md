# v0.8.7: 印字根拠のある単価・数量の関連付け

## 引き継ぎとv0.8.6レビュー

Issue #11、draft PR #10、source `0b5ce867ef264e0daaa15222474ab5c5c71a75d5` を基準とした。
実機の匿名診断は `smallHeading/countHint/amountColumn/sumMatches=true`、`futureSummary=false`、`labelKind=OTHER`。
小計の見出しが「小辻」かどうかは視認上の推定であり、実コードポイントは未確認。
v0.8.6の限定的な「小辻」対応を維持する。見出し一致だけで小計を確定せず、後続集計が無ければ保留する。
レビューで、全商品の数量が既知でも印字点数の上振れを許す条件を発見した。
数量不明が無い場合は点数の完全一致も要求し、合計金額が偶然一致する本物の商品を誤除外しにくくした。
未知数量がある場合の最低点数は分類の整合性にのみ用い、各商品の数量を補完しない。
同じ金額・見出し・位置・点数を持つ本物の商品との完全な判別は保証できず、保留の原文確認は必要。

## `? × ?` のコード上の原因と修正

- `UNIT` / `UNIT_ONLY` は `@` と金額の間の空白を許していなかった。
- 商品名と同じ行にある `79円×2点 158C` は、従来の `UNIT` に必要な先頭記号がなく未抽出。
- `79円×2点=158円` の明示式、`単価79円 数量2点` と逆順、その空白消失を扱えていなかった。
- 同じ行の独立した中央検出領域 `79×2点` は、座標があるのに名称へ残った。

今回、これらを印字根拠付きで対応する。中央列は独立領域・右隣の金額欄・領域非重複を条件とし、
単価×数量と行金額の一致を必須にする。別行の式は隣接する自分の商品だけに関連付け、
式内の合計と商品行金額も照合する。範囲外の式内合計や不一致は関連付けない。
価格を読み落とした前商品の名称を、次の単価・数量・金額が揃った商品へ折返しとして付加する既存の誤結合も再現し、抑止した。容量だけの折返しは維持する。
等号や数量表記の分離後も、商品名・容量・型番は可能な限り印字を維持し、原文は端末内詳細に残す。
匿名診断には `unitKnown` / `quantityKnown` の真偽値だけ追加し、値・名称・原文は追加しない。

実機原文・座標は取得していないため、この取りこぼしが本人の全未確定行の原因とは断定しない。
数量を印字していない単一購入品は引き続き未確定になる。行金額=単価、購入総点数、容量から数量1を作らない。
税込単価・税率の推定、候補の自動選択・保存は行わない。

## 試験

`tests/shared/ReceiptPairingTest.java` をJVMとAndroid instrumentationの双方から実行。
同一の架空データでv0.8.6を調査した10書式は全て単価・数量未抽出。新テストは同じ10書式、
中央列、式の不一致、容量・型番・集計に似た実商品、隣接商品への数量流用を確認する。
従来の79×2=158、245×2=490と359円商品に数量2を流用しない回帰も維持する。

6/20/50商品では架空座標をランダム順で与え、商品名・順序・各数量・単価・行金額・小計・税・合計を検証。
折返し容量、混在税率、管理行、値引、途中の商品OCR欠損も検査する。
これは**認識後の解析試験**であり、20/50行の画像をOCRして全商品を検出できる証明ではない。
実際に両OCRで同じ画像を読む既存Android合成画像試験も別途維持する。

80検出領域、80候補、4百万画素、32000文字等の既存上限は拡張しない。
50商品試験は複数列を結合した領域を含む66領域。50商品の名前・金額が別領域になると80を超え得る。
その場合は既存の分割案内が必要で、長い実レシートへの実用対応は未達。81領域を拒否する境界試験も維持。
解析時間の標本はテスト出力に記録するが、実機OCR時間やピークメモリとは区別する。

## 三原則と配布

- 機能: 名称・価格・数量の関連付けと逆方向検査。DB/JSON形式・買い物メモ・保存方式を変更しない。
- プライバシー: アプリ通信権限、SDK、モデル、外部Intentを追加しない。実データは利用しない。
- セキュリティ: 入力上限・価格/数量範囲を維持。不整合を自動確定しない。最終APKも検証する。
